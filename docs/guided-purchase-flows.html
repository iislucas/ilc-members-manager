Guided Purchase Flows

Five pages walk a member through buying something, and the grading workflow shows progress through a similar sequence. They share three pieces rather than each rolling their own numbered sections.

The three pieces

PieceFileRole
<app-step-track> src/app/step-track/step-track.ts The 1 — 2 — 3 line at the top.
<app-step-card> src/app/step-card/step-card.ts One numbered stage: expanded, collapsed, or not yet reached.
StepFlow src/app/step-track/step-flow.ts The bookkeeping that decides which is which.

Step 1 of every purchase flow is <app-inline-auth> — see Authentication. All five are public routes; see Public vs Gated Views for why.

The idea

Only the step the user has to do now is expanded. Steps already done collapse to a one-line summary they can reopen; steps not yet reached render a muted header so the sequence is visible, but their content is not in the DOM at all.

Why the pattern exists

The pages previously rendered every form at once and disabled the ones that were not ready (opacity: 0.6; pointer-events: none). Fields looked like fields, clicked like nothing, and never said why — people reported being unable to type into the form.

Driving it

A page states only which step is the first one still needing work. StepFlow turns that into per-step states and handles the user jumping back: 

readonly StepAccount = 1;
readonly StepDetails = 2;
readonly StepPayment = 3;

flow = new StepFlow(
  computed(() => {
    if (!this.isLoggedIn()) return this.StepAccount;
    if (!this.hasCompletedDetails()) return this.StepDetails;
    return this.StepPayment;
  }),
  ['Account', 'Details', 'Payment'],
);

The template then needs no step logic of its own:

<app-step-track
  [steps]="flow.steps()"
  [navigable]="true"
  (stepSelected)="flow.goTo($event + 1)"
></app-step-track>

<app-step-card
  [number]="StepDetails"
  title="Your Details"
  [state]="flow.stateOf(StepDetails)"
  [expanded]="flow.current() === StepDetails"
  (editRequested)="flow.goTo(StepDetails)"
>
  <span stepSummary>{{ detailsSummary() }}</span>
  …fields…
</app-step-card>
Steps re-open themselves

Because "first incomplete" is derived from the data, a step re-opens by itself the moment its answer stops being valid. Clearing a required field on step 2 pulls the user back to it rather than stranding them on step 4. flow.goTo() layers an explicit jump on top, honoured only while everything before it is still complete.

MemberDoes
flow.current()The one expanded step (1-based, matching the numbers shown).
flow.steps()Per-step states for the track.
flow.stateOf(n)todo | current | done | review.
flow.goTo(n)Jump to a step, e.g. from an Edit button.
flow.next()Move on — never skips past unfinished work.
flow.resume()Drop a jump and return to the outstanding step.

Steps that must not be skipped

A step whose answer is already valid would be stepped straight over. That is right for details a returning member has given before; it is wrong when the step carries a choice.

The bug this prevents

On Become a Member the annual option is preselected and immediately valid, so without an explicit acknowledgement the flow would carry the user to Payment for something they never chose. 

private membershipStepAcknowledged = signal(false);
// …in the firstIncomplete computed:
if (!this.membershipStepAcknowledged()) return this.StepMembership;

Such steps gate on a …Acknowledged signal that their Continue button sets. The same applies to:

  • Next Grading — free retake vs. buying the next level in advance.
  • Instructor License — licence status worth reading before paying.
  • School License — renewing with no schools on record otherwise counts as complete.

States and colours

All four come from the standard palette in src/scss_variables.scss — no component-local colours.

StateMarkerMeaning
todoWhite, dashed neutral borderNot reached; content not rendered.
current$separator-color grey with a solid $brand-red outlineThe work to do now.
done$highlight-tag-* light blue with a tickComplete; collapsed to a summary.
reviewSolid neutralReached, but waiting on someone else (grading workflow).

Red marks where your attention goes, which is consistent with its use for errors. Blue for "done" is the palette's documented role for stage checkmarks — grading-progress previously used a hardcoded green #28a745 here and was brought into line.

Greens that stayed green

Greens elsewhere in the grading UI mean passed or saved, not "stage complete", and are deliberately left alone.

Shared styles

.step-guidance, .step-footer and .step-todo-hint live in the global src/styles.scss, not in step-card. Content projected into <app-step-card> keeps its own page's style scope, so component-scoped rules there would not reach it.

<app-step-track> sets no bottom margin: the flow containers are flex with a 1.75em gap, and a margin on the track stacked on top of it into a ~52px void. Spacing below the track is the consuming page's business.

Tests

SpecCovers

Each page's own spec Its gating — e.g. become-a-member.spec.ts asserts the user is never sent to pay for a membership they did not confirm.
